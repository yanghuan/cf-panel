## 2. 安全

### 2.1 复核通过（本轮再次逐项确认）

1. 凭据落库全哈希：agent key HMAC（`hashSecret`，`HASH_SECRET` 优先 / `JWT_SECRET` 回退）；`agent_key_id` 无盐 SHA-256 仅作检索键（256 位熵，不可逆推）；PAT 只存哈希、明文仅返回一次。
2. JWT：无 `alg` 混淆（`verifyJwt` 不读 header，固定 HS256）；`exp` 校验；`secret()` 缺失即 throw（无默认密钥），全入口 fail closed（含 `/ws/push`、`/mcp`、签名上传路径）。
3. WS 鉴权：token 不进 URL（首帧 `{type:'auth'}`）；`user-pending` 鉴权前不挂接数据流；PAT 终端 10s 节流重校验；PanelDO 撤销即 `close(1008)`；agent 数据流 `X-Agent-Key` + stream 归属校验。
4. 上传签名 URL：HMAC 绑定 `server_id|path|overwrite|exp`、10 分钟过期、恒定时间比较；验签路径同样要求 `JWT_SECRET` 存在。
5. MCP：每请求 Bearer 鉴权 + Origin 同源校验（防 DNS rebinding）+ 管理类工具 `requireAdmin`（PAT 一律拒绝）；`exec_command` 审计已补（上轮 M1）。
6. agent：`wss://` 强制（userinfo 伪装正确剥离，有测试）、`DISABLE_EXEC` 覆盖终端/文件/exec/上传四条路径、入站 64KB/8MB/1MB 上限、系统路径黑名单、`upload_id` 白名单、offset 严格校验、临时文件会话级清理、进程组 kill 防孤儿。
7. 上报入口 `sanitizeReportPayload` 一处收口（上轮 M2 修复有效）：数值归一化、extra 键白名单、条数/体积上限，且覆盖新增的 `disk_io` 嵌套对象（有专项测试）。
8. `.gitignore` 覆盖 `.dev.vars` / `.wrangler` / `agent/rust/target`（复核：target 未被 git 跟踪，git ls-files 仅 63 个文件）；`gen-dev-vars.sh` 用 `umask 077`。
9. 前端：CSP `script-src 'self'`（无 inline/eval）、`connect-src` 无 ws 通配（上轮 L11 修复有效）、主要输出点 `escapeHtml`、登录限流（5 次/15min）。

### 2.2 新发现

- **M1（文件管理 WS 上传（write）审计实际不生效——协议路径错位）**：`do-terminal.js:630-656` 的 `file.write` 审计代码块位于 `typeof message === 'string'` 分支内，仅对 **Text JSON 帧**生效。但生产路径的前端上传（`api.js:110-135` `_sendNextUpload`）发送的是 **Binary 混合帧**（JSON 头 + 原始字节），E2E 客户端 `e2e-file.mjs:45-48` 同样。Binary 帧在 `webSocketMessage` 中直接透传，**审计块永远不会执行**。后果：面板文件管理器上传文件无 `file.write` 审计（`file.open`、`file.zip`/`file.rename`/`file.delete` 均正常），与 README「文件写操作（上传/打包/重命名/删除）均记录」的声明不符；`test/do.test.js:1109` 的审计测试用 Text 帧（`JSON.stringify`），恰好覆盖不到生产路径——**测试与生产路径错位**是本项长期逃逸的根因。
  说明：`/mcp/file_upload` 与签名 URL 两条上传路径在 `routes.js` 有独立的 `file.upload` 审计，不受影响；缺的是**面板文件管理器 WS 上传**这一条。修复：在 Binary 帧处理路径解析帧头 JSON（`'\n'` 前部分），对 `type==='write' && offset===0` 记 `file.write` 审计；同时把测试改为 Binary 帧。

- **M2（`PANEL_USERS` 密码不可含逗号（密码可为任意串的语义被静默截断））**：`PANEL_USERS` 的解析先按 `,` 切用户、再按第一个 `:` 切用户名/密码。README 明确写「密码可含 `:`（按第一个冒号分割），建议不含 `,`」——即密码规则是「除 `,` 外任意字符」。当前**建议**而非拒绝，`alice:pass,1` 会被静默解析成两个用户 `alice:pass` 和 `1`（无冒号条目被丢弃），结果：真实密码 `pass,1` 永远登录失败、凭空多出半截密码的用户。属文档已知限制，但建议把「建议不含」升级为「必须不含」（parse 层显式拒绝含逗号条目并返回 500 配置错误），fail closed 优于静默截断；或在 README 显式声明「密码不得含逗号」并在文档标注为硬约束。

### 2.3 低风险加固项（本轮 Low）

- **L1（审计日志 CSV 导出未做公式注入防护）**：`routes.js:550-551` 的 `esc` 只做双引号转义，未对 `= + - @ \t \r` 前缀做防护。`detail`（exec 命令、服务器名、文件路径）与 `username` 是部分用户可控字段；管理员在 Excel/WPS 打开导出的 CSV 时可能触发公式执行。经典 CSV injection，防护一行即可（前缀加单引号或 `\t`）。
- **L2（Webhook URL 无协议/地址校验）**：`sendWebhookRaw`（`utils.js:254`）对管理员配置的任意 URL 直接 `fetch`，无 `http/https` 协议白名单、无私有网段检查。仅管理员可配置（self-SSRF），且 Workers 边缘网络默认不可达用户内网，现实风险低；若用户同时使用 Cloudflare 私有网络互通能力则风险上升。建议：校验协议为 `http(s)`，必要时拒绝 `file://` 等奇形 scheme。
- **L3（登录限流可被伪造 XFF 绕过（仅非生产路径））**：`clientIp`（`routes.js:182-188`）以 `cf-connecting-ip` 优先，但回退 `x-forwarded-for`。生产有 CF 前置注入，安全；**本地 `wrangler dev` / E2E 环境无 CF 头，攻击者可伪造 XFF 每请求换 IP 完全绕过限流**。本地调试场景可接受，但建议 dev 环境回退时对 XFF 取固定值或忽略（`'unknown'` 更安全），或在注释标注该边界。
- **L4（`agent.sh` 已废弃但仍含真实密钥路径与明文传输逻辑）**：废弃代码保留为参考（README 已标注），维护成本低，不列。

### 3.2 新发现

- **L5（前端监控实时更新 `monitorLive.tsArr` 在每图表循环内重复 push/shift）**：`app.js:1029-1033`：
  ```js
  if (append) {
    lc.chart.data.labels.push(label);
    lc.chart.data.labels.shift();
    monitorLive.tsArr.push(minTs);
    monitorLive.tsArr.shift();
  }
  ```
  该块位于 `for (const lc of monitorLive.charts)` 循环体内。`lc.chart.data.labels` 每个 chart 独立、操作正确；但 `monitorLive.tsArr` 是共享的，**每个 chart 都 push 一次 `minTs` 并 shift 一次**——N 张图时窗口被整体右移 N 位、`tsArr` 尾部出现 N 个重复 `minTs`（应为 1 个）。当前影响很小：`tsArr` 只被用于 `lastTs` 判断（尾部值恰好仍是 `minTs`，判定结果不变量正确）与 `maxLen`；但 `tsArr` 内容已损坏，一旦未来用它做索引/对齐（如按 ts 对齐 dataset）会踩坑。修复：把 `monitorLive.tsArr` 的两行移到循环外执行一次。
- **L6（Worker 侧服务器列表无"切快采 30s 过渡期"，首观者上线时 REST/MCP 列表可能短暂误判离线）**：PanelDO `buildList` 有 `PANEL_SWITCH_GRACE_MS=30s` 过渡期（0→1 观看者后 30s 内用慢宽限 180s）；而 `auth.js:114` `listServersWithState`（`GET /api/servers` 与 MCP `list_servers` 共用）直接按 `hasPanelViewers` 选择 15s/180s，**无过渡期**。慢采 120s 的 agent 在首个观看者上线后的 30s 内尚未切快采上报，此时 REST/MCP 列表会显示离线（主面板走 `/ws/push` 的 PanelDO 有过渡期不受影响，前端 `loadServers()` 首帧与 PAT 提示、MCP 客户端会短暂看到离线，约 5-10s 后推送纠正）。修复：`listServersWithState` 复用 PanelDO 的过渡期语义（需把 fastSince 存到 DO Storage 或按 viewers 接口返回过渡标记），或接受该短暂不一致并记录。
- **L7（文件写审计（WS 路径）无 `client_ip` 字段）**：`do-terminal.js:647-648` 的 `file.*` 审计 INSERT 缺 `client_ip`（REST 入口均有）。WS 消息路径拿不到请求 IP，需在挂接时从请求头取并随会话存储。低价值、可记录接受。
- **L8（`e2e-file.mjs` 未纳入 `npm test` 自动执行）**：脚本存在但 `test:e2e` 只跑 `e2e.mjs`（其内部会调用 e2e-file 吗？经查 `e2e.mjs` 用独立 Node 客户端内联上传逻辑，e2e-file.mjs 为独立工具）。作为独立工具可接受，记录即可。
