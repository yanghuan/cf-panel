## 1. 概览

Cloudflare Workers 单文件面板（D1 + 3 类 Durable Object + WebSocket Hibernation + Pages assets），Rust agent 常驻被控机（控制通道 + PTY 终端 + 文件管理 + 监控采集）。架构分层清晰：Worker 路由 → TerminalDO（WS 中转，4 分片）/ MetricsDO（时序热区+归档+告警）/ PanelDO（观看者推送）。

**总体评价**：工程完成度非常高。鉴权纵深、成本优化（观看者驱动快慢采、上报聚合、热区+增量归档）、可靠性（重连退避、确认重发、DO 水合、幂等、TTL 回收）均已系统化，注释详实到"每个优化都写了原理与边界"。发现 **1 High / 2 Medium / 8 Low**，其中 High 为前端权限判定的功能性缺陷（服务端安全不受影响）。

## 2. 安全

**逐项核验通过**：

1. 凭据落库全哈希：agent key 用 HMAC（`hashSecret`，HASH_SECRET 优先、JWT_SECRET 回退）；`agent_key_id` 为无盐 SHA-256 仅作检索键；PAT 只存哈希、明文仅显示一次。
2. WebSocket 首帧鉴权：token 不进 URL（防访问日志/历史泄露）；`user-pending` 附件角色防未鉴权数据流向。
3. PAT 撤销即时性：REST 每请求重查；终端 WS 10s 节流重校验；PanelDO 推送 `authCache` 5s TTL + 撤销清缓存 + 未授权连接主动 close（防观看者残留计数）。
4. DO 内部 RPC 不可外部直达（仅 stub 可达）；`/rpc/exec` 鉴权在 routes 层完成。
5. MCP：每请求 Bearer 鉴权 + Origin 校验（防 DNS rebinding）+ scope 白名单。
6. 前端：CSP（`script-src 'self'` 无 inline/eval）+ 全量 `escapeHtml`（逐一核对 cardHtml/metricTipHtml/renderFileList/loadTokens/loadAuditLogs）+ token 仅 localStorage + 登录限流（IP 窗口 5 次/15min）。
7. 文件管理：系统路径黑名单（重命名/删除/打包）；`upload_id` 字符白名单；offset 严格校验防乱序/并发错写；临时文件会话级清理；500MB 上限。
8. agent：`wss://` 强制（明文仅回环或显式开关，userinfo 伪装被解析剥离）；exec/终端受 `DISABLE_EXEC` 门禁；控制通道入站 64KB 上限。

**发现**：

- **H1（UI 权限判定缺陷，见 §6）**：`/api/me` 不返回 PAT scopes，前端 `canExec` 恒 false → 带 `server:exec` 的 PAT 用户终端/文件菜单被**错误隐藏**（功能不可用；服务端校验正常，非越权）。
- **L6**：MCP 响应 `access-control-allow-origin: '*'` 配合 Bearer 鉴权——攻击者无法让浏览器自动携带自定义 Authorization 头，实际风险低；可收窄为回显 origin 更严谨。
- **L7**：登录按密码匹配（`findIndex(u => u.password === password)`），多用户密码相同时身份取第一个；当前凭据模型下可接受，建议文档注明"用户名仅显示用途"。

## 3. 可靠性

**做得好的**：

- agent 重连退避（指数 + 抖动 + 存活 ≥10s 重置 + 401 长退避）——上一轮 review 修复的"健康连接被重置后退避单调膨胀"已生效。
- 控制通道指令确认重发（open_terminal/open_file，3 次 × 5s）；DO 休眠唤醒附件重建索引（Hibernation 兼容）；会话 TTL/绝对 TTL 双回收 + alarm 兜底。
- MetricsDO 热区以 DO Storage 为事实源（evict 恢复）、归档水位防回溯空洞（首帧兜底 + fullSweep 兜底 + 失败保持水位）、家政时间戳持久化防 evict 停摆——归档正确性的边界注释极为详尽。
- 文件上传 stop-and-wait + 严格 offset + fsync + 原子 rename；下载 EOF 提前中止 + Blob 直引；zip 临时文件清理闭环。
- MCP exec：三层超时协调（DO 兜底晚 5s）、进程组 kill 防孤儿、`pendingExec` 断连统一失败、resolve 幂等。

**发现**：

- **M2（控制通道上报异常被静默吞掉）**：`do-terminal.js` `webSocketMessage` 中 `handleReport` 抛错被最外层 `catch { /* 忽略非 JSON 的控制消息 */ }` 一并吞掉——MetricsDO 瞬时不可达（故障/重启）时该帧丢失、`last_seen` 不更新且无重试，面板在宽限期后误判离线（下一帧自愈，影响 ≤ 快采周期）。建议：report 分支单独 try/catch 并记日志；HTTP 路径 `/api/report` 的 `handleReport` 抛错会直接 500（无 catch），行为也不一致。
- **M3（settings 非法类型 500）**：`PUT /api/settings` 传 `alerts` 为非对象（如字符串）→ `sanitizeAlerts` 返回 `undefined` → `kvPut` 对 `undefined` 做 `JSON.stringify` 得 `undefined` → D1 bind 报错 500。建议：`sanitizeAlerts` 返回 `{}` 而非 `undefined`，或 routes 侧判空。
- **L3（审计与主操作非事务）**：POST /api/servers 先 INSERT server 再 INSERT audit，audit 失败返回 500 但服务器已创建（前端显示失败实已生效）。D1 写极少失败，属边缘。
- **L4（删除后 PanelDO 列表缓存未清）**：DELETE /api/servers 清 Worker 侧 `serverListCache`/`serverRowCache`，但 PanelDO 实例内 `listCache`（TTL 4.5s）未清——已删服务器最多 4.5s 内仍出现在推送列表，点击后 404。影响极小，可加 `/rpc/clear_list_cache`。
- **L8（agent SIGKILL 时 PTY 残留）**：agent 被 SIGKILL（非正常退出）时 bash 子进程成孤儿；依赖 systemd 默认 `KillMode=control-group` 兜底。Docker/裸跑场景需自行保证。

## 4. 性能与成本

**做得好的**（本项目的核心工程点）：

- **观看者驱动快慢采**（5s/120s）：PanelDO 0→1/1→0 事件广播切分片；上报驱动推送（MetricsDO → PanelDO，出站不计费）；无观看者零推送。
- **上报链路节流**：Worker/TerminalDO 侧 5s 聚合批转发（多机合并）；last_seen D1 60s 节流；custom 分钟去重；info/probe 变更才写；行缓存 60s TTL。
- **查询链路**：`serverListCache` 2s 用户维度缓存；PanelDO listCache 4.5s / latestCache 4s；MetricsDO `/latest` O(S) 增量维护；归档 `INSERT OR IGNORE` 幂等。
- **前端**：增量 DOM 更新（不重建卡片）、离线老化每秒仅碰徽章、降采样 240 点、事件委托、geo 并行 + 7 天持久缓存 + 私网过滤。
- **agent**：采集并行 `join!`、disk 60s 缓存熔断、info 10min 缓存、阻塞信号量限并发、终端合帧 16ms/32KB（DO 消息数 −60~75%）、日志 mpsc 有界队列。

**发现**：

- **M1（目录打包全量读入内存）**：`file_zip`/`zip_directory` 将整个目录递归读入单个 `Vec<u8>`（无总大小上限，500MB 限制仅作用于单文件 read）——大目录（如含 10GB 视频的目录）打包会 OOM；`blocking_with_timeout(120)` 超时后 spawn_blocking 任务无法取消，内存持续增长直至写完。建议：递归前统计目录总大小（或按条目预算）设上限，超限返回错误。
- **L9（exec 输出无界物化）**：agent exec 的 `read_to_end` 先完整收集再 44KB 截断——25s 窗口内刷屏命令峰值内存可达数百 MB。建议 `take(44KB+ε)` 有界读取。
- **L10（alarm 退避误判）**：`alarm()` 中 `getAlertCfg` 抛错（D1 故障）时 `alertOn` 保持 false，与 `data.size===0` 组合可能误判"闲置"退避 1h——归档/离线告警最长停摆 1h，D1 恢复后由 scheduleArchive 拉回。边缘。

## 5. 逻辑验证（关键点，防误改）

- 在线判定链：MetricsDO `last_seen_s`（秒级）→ D1 `last_seen`（60s 节流兜底）→ 前端 20s 老化；快/慢宽限 + 30s 切快采过渡期（防慢采周期误判离线）——三处判定口径一致。

- 归档水位推进条件严格（D1 写成功才推进、兜底失败保持水位 + `pendingArcRetry` 重试标记），注释对每个边界（时钟回拨/evict 首帧/滞后行）均有论证。
- 前端推送：`pushWs !== ws` 旧连接防干扰；1008 清登录态防死循环；后台标签页关 WS / 空闲暂停 / 恢复状态机无冲突。
- MCP exec 鉴权：routes 层 `canExec` → DO `/rpc/exec` 信任内部 → agent 侧 `DISABLE_EXEC` 门禁——三层纵深正确。
- 服务器修改（PATCH）：不动 agent key / hash，重名/空名校验，审计 detail 记录 `旧名 → 新名`——新增功能验证正确。
